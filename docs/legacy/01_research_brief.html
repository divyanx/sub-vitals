§ 01

Devvit platform anatomy

Two flavors, one platform. Knowing which to pick decides 80% of your architecture.

FLAVOR A

Classic Devvit (Blocks)

Renders inside Reddit using Reddit's own block components — vstack, hstack, text, button, image. No HTML, no CSS. Feels 100% native because it literally is Reddit's rendering engine. Best for in-feed widgets, post actions, modqueue overlays, mod notifications.

FLAVOR B

Devvit Web (WebView)

A Vite-built React/HTML/CSS app served inside an iframe-style webview. Backend uses Hono. Full HTML/CSS freedom. Best for analytics dashboards, complex forms, data viz. Tradeoff: feels slightly less Reddit-native, but unbeatable for rich UIs.

Decision

BrandPulse uses both. Classic Blocks for menu actions, modqueue annotations, post-level UI. Devvit Web for the full analytics dashboard. One devvit.json, one app, two render surfaces.

Critical Gotcha (from Devvit Reddit thread, June 2024)

ModAction triggers can't be filtered at registration. You subscribe to all mod actions, then filter the type in your handler. Same for most events. Plan for this in your trigger handlers — keep them fast.

§ 03

Native UI standards

If it doesn't look like Reddit, mods will know within seconds. Here's how to disappear into the platform.

Block primitives (Classic Devvit)

Devvit provides a Flutter/SwiftUI-style declarative block system. You compose UIs from these primitives:

ComponentPurposeNotes
<vstack> / <hstack> / <zstack>Layout containersgap, padding, alignment props
<text>Typographysize: xsmall/small/medium/large; weight: regular/bold
<button>Tap targetappearance: primary/secondary/destructive/plain
<image>Image renderingimageWidth/imageHeight required; URL or asset
<icon>Reddit's icon setname="info" / "alert" / "checkmark" etc.
<spacer> / <divider>SpacingUse generously — Reddit favors breathing room
<avatar>User avatarAuto-sized, looks native

The @devvit/kit helpers

Reddit ships an official helper library at github.com/reddit/devvit-kit:

  • Columns — multi-column layouts with gap control (block UI doesn't have this natively)
  • Item pagination — paginate any data list with built-in nav controls
  • PixelPadding — pixel-precise padding (default Devvit padding is fixed scale)
  • Developer toolbar — dev-only debug overlay; hide in production
  • Watermark — the official "Built on Developer Platform" badge

Visual conventions Reddit's own apps follow

01

Restrained color

Reddit Orange (#FF4500) for primary actions only. Everything else is neutral grey or transparent. Avoid color used decoratively.

02

Generous spacing

Padding: medium by default. Density isn't a virtue in Reddit's UI. White space signals legitimacy.

03

Toast confirmations

ui.showToast({appearance: 'success', text: '...'}) for every mod action. Mods expect this acknowledgement.

04

Forms over modals

Reddit prefers full forms (useForm) over inline edits. Open a form, mod fills it, submit. Familiar workflow.

05

Icon + label

Every button gets both an icon and label. Icon-only buttons feel unfinished in Reddit's design language.

06

Mod-only affordances

Use the mod shield icon for mod-only features. Hide them from non-mods using permission checks in onPress.

For the Devvit Web dashboard

Inside the webview, you have full HTML/CSS freedom — but to feel native:

  • Use Reddit's CSS variables when available (--color-primary, etc) — they cascade in
  • Match Reddit's font stack: IBM Plex Sans, system-ui, sans-serif
  • Border radius: 8px on cards, 16px on pills (matches Reddit's rounded language)
  • Dark mode is the default for most Reddit users — design dark-first
§ 04

Permissions, auth & settings

Two scopes, two purposes. Get this wrong and your secrets leak or your config gets confused.

ScopeWho can editUsed forBrandPulse example
App SettingScope.App Only the developer (you), via devvit settings set CLI Global API keys, encrypted secrets (isSecret: true) openai-api-key, gemini-api-key, stripe-key
Installation SettingScope.Installation Mod of the subreddit that installed the app Per-subreddit config — taxonomies, whitelists, feature toggles Agent username whitelist, taxonomy categories, sentiment threshold

Settings configuration page lives at: https://developers.reddit.com/r/SUBREDDIT/apps/APP_NAME

Example registration

import { Devvit, SettingScope } from '@devvit/public-api';

Devvit.addSettings([
  {
    type: 'string',
    name: 'openai-api-key',
    label: 'OpenAI API key (for AI tagging)',
    scope: SettingScope.App,
    isSecret: true,
  },
  {
    type: 'paragraph',
    name: 'agent-whitelist',
    label: 'Verified agent usernames (one per line)',
    scope: SettingScope.Installation,
  },
]);
Known bug

If you change a setting from App to Installation scope (or vice versa) after deploy, the old secret still shadows the new one. Mods see their config but the app reads the old value. Pick a scope and stick with it — pre-plan scope decisions in the data model.

Authenticating mod actions

Inside any handler, check the calling user's permissions before mutating:

const currentUser = await context.reddit.getCurrentUser();
const isMod = await context.reddit.getModerators({
  subredditName: context.subredditName!
}).all().then(mods => mods.some(m => m.username === currentUser?.username));

if (!isMod) {
  context.ui.showToast({ appearance: 'neutral', text: 'Mod-only action' });
  return;
}
§ 05

Storage patterns (Redis)

Devvit ships Redis as the primary storage. No SQL, no Postgres. Design your keys carefully.

Enable in Devvit.configure:

Devvit.configure({
  redditAPI: true,
  redis: true,
  http: true,    // for AI provider calls
});

Recommended key scheme for BrandPulse

Key patternValue typePurpose
bp:taxonomy:{sub}JSON arraySubreddit's issue category taxonomy
bp:tag:{postId}JSONTags for a specific post (driver, sentiment, agent role)
bp:agent:{sub}:{username}stringVerified agent: "verified" / "lead" / "removed"
bp:drivers:idx:{sub}:{driver}sorted setIndex of posts by driver, scored by timestamp
bp:sentiment:rollup:{sub}:{day}JSONDaily sentiment aggregate (avg, count, distribution)
bp:response:{postId}JSONFirst-response time, resolution status
bp:pii:log:{sub}sorted setAudit log of PII redactions
bp:config:{sub}JSONPer-subreddit feature toggles

Operations available

  • redis.get(key) / redis.set(key, value, options?) — basic string ops
  • redis.zAdd(key, {score, member}) / redis.zRange(key, start, stop) — sorted sets (perfect for time-ordered post indexes)
  • redis.hSet(key, {field: value}) / redis.hGetAll(key) — hash maps
  • redis.incrBy(key, n) — counters (daily volume, sentiment tallies)
  • redis.expire(key, seconds) — TTLs (cache, rate limits)
Storage scope

Redis is scoped per installation. Every subreddit that installs BrandPulse has its own isolated Redis namespace automatically. You don't manage tenancy — Devvit does. Treat keys as if your sub is the only one.

§ 06

Triggers & scheduler

Where event-driven logic lives. The brain of every passive feature.

Trigger event types

EventFires onBrandPulse usage
PostSubmitNew post createdAuto-tag with contact driver, sentiment, PII scan
CommentSubmitNew commentIf by agent → log response time; sentiment
PostReport / CommentReportUser reports contentAdd to modqueue priority list
ModActionAny mod action (broad)Track resolution events, mod activity for QA
PostUpdatePost editedRe-scan for PII, update tags if substantive edit
AppInstallApp installed in a subSeed default taxonomy; show welcome modmail
AppUpgradeMod upgrades versionRun migration scripts
ModMailMod mail eventsDetect escalation patterns

Trigger registration

Devvit.addTrigger({
  event: 'PostSubmit',
  onEvent: async (event, context) => {
    const { post } = event;
    if (!post) return;

    // Run all module handlers in parallel
    await Promise.all([
      tagContactDriver(post, context),
      scoreSentiment(post, context),
      scanPII(post, context),
    ]);
  },
});

Scheduler jobs

Devvit scheduler supports cron expressions and one-off delayed jobs. Configure recurring jobs:

Devvit.addSchedulerJob({
  name: 'daily-aggregate',
  onRun: async (_event, context) => {
    // Roll up yesterday's tags, sentiment, response times
    await rollupYesterday(context);
  },
});

// Kick off at AppInstall:
await context.scheduler.runJob({
  name: 'daily-aggregate',
  cron: '0 2 * * *', // 02:00 UTC daily
});

Module isolation principle

Every module lives in its own folder and exposes a uniform interface:

// src/modules/<module>/index.ts
export interface Module {
  name: string;
  enabled(ctx: Context): Promise<boolean>; // feature flag check
  onPostSubmit?(event, ctx): Promise<void>;
  onCommentSubmit?(event, ctx): Promise<void>;
  registerMenuItems?(): MenuItem[];
  registerApiRoutes?(app: Hono): void;
}

Each module is registered in main.ts. A central dispatcher fans out trigger events to all registered modules. If one module throws, the others continue.

Storage
bp:agent:{sub}:{username} → role string

CORE Phase 1

The taxonomy-tagging engine. Every post gets categorized so brands see why customers are coming.

Native UI
Post menu: "Tag Issue" — opens form with taxonomy dropdown
Triggers
PostSubmit → auto-suggest tag (Phase 2: AI-powered)
Custom Post
"Daily Pulse" pinned post showing top 5 drivers from last 24h

Installation-scope: JSON-editable taxonomy tree
Web Dashboard
"Drivers" tab — bar chart of volumes, time-series, drill-down to posts
Scheduler
Daily 02:00 UTC — aggregate yesterday's tags into rollup keys

GET /api/drivers/volume?from&to · POST /api/drivers/tag
03 · Sentiment Dashboard (CSAT)
CORE Phase 1

Real-time sentiment scoring on threads. Flag escalating negative threads before they go viral.

Triggers
PostSubmit + CommentSubmit → score sentiment, store
Native UI
Post menu: "View Sentiment Trail" — modal showing thread sentiment over time
Modmail
Real-time alert: "Thread X is going negative — 5 angry comments in 10 min"
Web Dashboard
"Sentiment" tab — heatmap calendar, trend lines, escalation feed
04 · PII Guardian (Auto-Redaction)
PRO Phase 2

Detects passwords, emails, phone numbers, API keys, addresses in posts/comments and either alerts mods or auto-redacts.

Triggers
PostSubmit + PostUpdate + CommentSubmit → scan content
Native UI
Menu: "Redact PII" — manual trigger; shows what would be redacted before confirming
Settings
Toggle: auto-redact / alert-only; threshold sensitivity
Web Dashboard

05 · Response Analytics
PRO Phase 2

Tracks how fast agents respond to customer posts, resolution rates, backlog. First-response time SLA monitoring.

Triggers

Scheduler
Every 15 min — scan unanswered posts, flag SLA breach in modmail
Web Dashboard
SLA dashboard: avg first response, resolution rate, agent leaderboard
06 · AI Content Detector ("Slop Filter")
PRO Phase 3

Detects likely AI-generated posts and comments. Cornell research says 67% of mods rank this as their #1 concern.

Triggers

Native UI

Settings
